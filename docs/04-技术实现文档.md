### 1.2 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| **生成编排** | YAML + Python Orchestrator | 五 Agent 顺序执行、Mock/真实 LLM 双模式 |
| 后端 API | Python 3.11 + FastAPI | 异步友好，与 AutoGen 同生态 |
| 任务队列 | Celery + Redis | 长时案例生成异步化 |
| 数据库 | PostgreSQL 15 | 案例 JSON + 关系数据 |
| 前端 | React 18 + TypeScript + Vite + TailwindCSS | 教师工作台 SPA，详见 `07-前端技术实现文档.md` |
| LLM | GPT-4o / DeepSeek | 通过 `llm_config` 注入 AutoGen |
| 导出 | python-docx + ReportLab + python-pptx | Word、PDF 授课包与可编辑 PPTX 课件 |
| 配置 | YAML + Pydantic | Agent 与编排可配置 |
| 部署 | Docker Compose + Nginx | 常驻服务；前端 5173、后端 8010，均监听 `0.0.0.0` |

### 1.3 当前实现边界

当前线上编排器直接读取五份 Agent YAML：默认 Mock 模式用于无模型密钥的稳定演示；配置 `OPENAI_API_KEY` 且关闭 Mock 后，通过 OpenAI 兼容接口逐 Agent 生成。AG2/GroupChat 属于可替换的后续编排实现，不应在上线说明中写成已启用能力。

四项 Application Skills 会按 Agent 与任务上下文渐进加载：`design-instructional-plan`、`apply-case-pattern`、`adapt-subject-context`、`validate-case-package`。Skill 使用轨迹写入案例元数据，确定性脚本负责教学目标生成和案例包质量门禁。

## 2. AutoGen Agent 详细设计

> 前端实现详见 [`07-前端技术实现文档.md`](07-前端技术实现文档.md)

### 2.1 Agent 配置体系（四层）

| 层级 | 内容 | 配置位置 |
|------|------|----------|
| L1 全局层 | LLM 接入、Token 预算、内容安全、日志保留 | `.env` / `config.py` |
| L2 角色层 | 各 Agent 的 Prompt、模型、Tool、输出 Schema | `app/agents/*.yaml` |
| L3 编排层 | Sequential / GroupChat、顺序、轮次、超时 | `workflows/templates/*.yaml` |
| L4 学科层 | 学科模板、术语表、Prompt 片段 | `agents/subjects/{id}/` |

### 2.2 Agent 配置示例（YAML）

```yaml
# agents/case_planner.yaml
name: CasePlanner
type: ConversableAgent
description: 教学案例结构策划专家
system_message: |
  你是资深教学设计专家，擅长将教学目标转化为案例结构。
  输出必须是合法 JSON，符合 CaseOutline Schema。
  案例必须包含：清晰决策点、角色冲突、可讨论的道德或战略困境。
  不得设计无讨论价值的平淡情境。
llm_config:
  model: gpt-4o
  temperature: 0.4
output_schema: CaseOutline
```

```yaml
# agents/domain_expert.yaml
name: DomainExpert
type: ConversableAgent
description: 学科与行业情境专家
system_message: |
  你是{subject}领域专家。基于案例大纲提供行业情境、专业术语、
  合理约束与角色设定。情境可为教学虚构，但内部逻辑须一致。
  禁止编造可识别的真实企业负面信息并暗示为事实。
```

```yaml
# agents/reviewer.yaml
name: Reviewer
type: ConversableAgent
description: 教学案例质量评审专家
system_message: |
  依据 Rubric 评审案例包：教学目标对齐(25%)、情境真实性(20%)、
  讨论价值(25%)、结构完整性(15%)、可读性(15%)。
  输出 JSON：scores, overall, pass(bool, 阈值4.0), revision_advice。
```

### 2.3 编排实现（Sequential MVP）

```python
# 核心编排伪代码 — backend/app/autogen/workflows/sequential_pipeline.py

from autogen import ConversableAgent, UserProxyAgent

def build_sequential_pipeline(llm_config: dict, agents_config: dict):
    teacher_proxy = UserProxyAgent(
        name="TeacherProxy",
        human_input_mode="NEVER",
        code_execution_config=False,
    )

    planner = ConversableAgent(
        name="CasePlanner",
        system_message=agents_config["planner"]["system_message"],
        llm_config=llm_config,
    )
    expert = ConversableAgent(name="DomainExpert", ...)
    writer = ConversableAgent(name="CaseWriter", ...)
    pedagogy = ConversableAgent(name="PedagogyDesigner", ...)
    reviewer = ConversableAgent(name="Reviewer", ...)

    # Sequential: TeacherProxy → Planner → Expert → Writer → Pedagogy → Reviewer
    teacher_proxy.initiate_chats([
        {"recipient": planner, "message": task_prompt, "max_turns": 1},
        {"recipient": expert, "message": lambda prev: prev.summary, "max_turns": 1},
        # ... 链式传递
    ])
```

### 2.4 GroupChat 评审循环（Sprint 2）

```python
from autogen import GroupChat, GroupChatManager

def build_review_groupchat(writer, pedagogy, reviewer, llm_config):
    groupchat = GroupChat(
        agents=[writer, pedagogy, reviewer],
        messages=[],
        max_round=6,
        speaker_selection_method="auto",  # 或自定义：Reviewer 不满意时指定 Writer
    )
    manager = GroupChatManager(groupchat=groupchat, llm_config=llm_config)
    return manager
```

## 3. 案例生成核心流程

```
1. API 接收 CaseTaskCreate → 写入 DB (status=pending)
2. 后台生成任务 `run_generation(task_id)`
3. Orchestrator 加载 Agent YAML、Application Skills 与任务上下文
4. 执行流水线，每步：
   a. 推送 WebSocket：agent_name, status, snippet
   b. 解析 Agent 输出 JSON
   c. 失败则重试 / 降级
5. Reviewer pass → 组装 CasePackage → 存 DB (status=completed)
6. 运行字数、结构、重复内容与目标对齐质量门禁
7. 存档 Rubric、Skill trace 和可导出的版本化案例包
```

### 3.1 导出服务（Word / PDF / PPTX）

```
CasePackage (JSON)
    │
    ▼
┌──────────────┐
│ 模板渲染器    │  Jinja2 变量注入（标题、四件套内容）
└──────┬───────┘
       ▼
┌──────────────┐
│ Word 生成器   │  python-docx：封面、目录、样式、页眉页脚
└──────┬───────┘
       │
       ├── format=docx → 直接返回 .docx
       │
       ├── format=pdf  → ReportLab 中文排版 → .pdf
       └── format=pptx → 内容重组 + python-pptx → .pptx
```

`format` 枚举为 `docx`、`pdf`、`pptx`。PPTX 支持 `theme=academic|modern|minimal`、`density=concise|standard|detailed`、`audience=teacher|student`；`POST /api/cases/{id}/ppt-outline` 返回导出前目录预览。所有文件使用主题名和案例包版本号命名。

## 4. 数据库设计

```sql
-- 用户（教师）
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    name VARCHAR(100),
    role VARCHAR(20) DEFAULT 'teacher',  -- teacher / admin
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 案例生成任务
CREATE TABLE case_tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    title VARCHAR(500) NOT NULL,
    subject VARCHAR(100) NOT NULL,
    course_name VARCHAR(200),
    case_type VARCHAR(50),
    difficulty VARCHAR(20),
    target_audience VARCHAR(50),
    learning_objectives JSONB NOT NULL,
    config JSONB NOT NULL,           -- 完整表单参数
    workflow_template VARCHAR(50) DEFAULT 'sequential',
    status VARCHAR(20) DEFAULT 'pending',
    error_message TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 案例包（生成结果）
CREATE TABLE case_packages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id UUID REFERENCES case_tasks(id) ON DELETE CASCADE,
    version INT DEFAULT 1,
    package JSONB NOT NULL,          -- CasePackage Schema 全文
    rubric_overall DECIMAL(3,1),
    status VARCHAR(20) DEFAULT 'draft',  -- draft / reviewed / finalized
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Agent 执行日志（教研调试）
CREATE TABLE agent_run_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id UUID REFERENCES case_tasks(id),
    agent_name VARCHAR(100),
    round INT DEFAULT 0,
    input_summary TEXT,
    output_summary TEXT,
    token_usage INT,
    duration_ms INT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Agent 配置版本
CREATE TABLE agent_configs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    agent_name VARCHAR(100) NOT NULL,
    version VARCHAR(20) NOT NULL,
    config_yaml TEXT NOT NULL,
    is_active BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 7. 核心实现步骤

### Phase 1：AutoGen 最小链路（Spike）

1. 安装 `ag2` / `autogen`，配置 `llm_config`
2. 实现 3 Agent：Planner → Writer → Reviewer
3. 硬编码教师参数， stdout 打印案例 JSON
4. 教研评审样例案例质量

### Phase 2：编排服务化

1. `agent_factory.py` 从 YAML 实例化 Agent
2. `sequential_pipeline.py` 完整五 Agent 链
3. Pydantic `CasePackage` 校验与组装
4. Celery 异步任务 + 状态机

### Phase 3：教师端与案例库

1. 案例配置 API + 前端表单
2. WebSocket Agent 进度
3. 四件套预览编辑 + 版本
4. 教学目标建议、质量门禁与案例包版本管理

### Phase 4：质量与导出

1. `rubric_service.py` + `evaluate_cases.py`
2. GroupChat 评审循环
3. Word / PDF / PPTX 导出与 PPT 目录预览
4. 管理员 Agent 配置页

### Phase 5：上线

1. Docker Compose 全栈
2. Token 与成功率监控
3. 种子用户测试与 Prompt 调优

## 8. 安全与合规

| 措施 | 实现 |
|------|------|
| 内容安全 | LLM 前置过滤 + Reviewer 违规检测 |
| 虚构声明 | `meta.fictional_disclaimer` 强制写入导出 |
| 认证与会话 | bcrypt 密码哈希；短时 Access Token；7 天或会话级 HttpOnly Refresh Cookie；生产环境 Secure Cookie + HTTPS |
| 数据隔离 | `user_id` 行级过滤 |
| 日志脱敏 | Agent 日志不记录完整 API Key |
| 版本锁定 | `ag2==x.y.z` 避免框架漂移 |

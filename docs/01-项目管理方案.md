# CaseAutoGenSystem 项目管理方案

> **文档版本**：v2.2
> **编制视角**：AI 项目管理经理  
> **方法论**：PMP 框架 + AutoGen 多智能体开发适配  
> **项目定位**：基于 AutoGen 的教学案例（Teaching Case）自动生成系统

---

## 1. 项目概述

### 1.1 项目背景

高校与培训机构大量依赖**教学案例**开展案例教学、翻转课堂与研讨式教学。传统案例开发周期长（数周至数月）、成本高、质量参差不齐，且难以快速响应新热点与跨学科需求。

**CaseAutoGenSystem** 的核心目标不是生成学术论文，而是构建一套基于 **Microsoft AutoGen（AG2）多智能体框架** 的**教学案例自动生成系统**：教师输入课程主题、教学目标、难度等参数后，由多个协作 Agent 自动产出结构化教学案例及配套教学资源。

### 1.2 项目基本信息

| 项目项 | 正式口径 |
|--------|----------|
| 项目启动时间 | 2026 年 5 月 |
| 系统上线时间 | 2026 年 8 月 |
| 团队规模 | 4 人 |
| 项目投入 | 人民币 15 万元 |
| 总体项目周期 | 2026 年 5 月至 8 月，其中核心 MVP 研发按 8 周 Sprint 管理 |

### 1.2.1 四人团队角色配置

| 角色 | 人数 | 主要职责 |
|------|------|----------|
| 产品/项目负责人 | 1 | 需求、排期、验收、商业化与教师反馈闭环 |
| AI/后端工程师 | 1 | 五 Agent 编排、Skills、质量门禁、认证与导出服务 |
| 前端工程师 | 1 | 教师工作台、长文阅读体验、PPT 配置与响应式交互 |
| 教研/测试与实施 | 1 | 教学案例 Rubric、跨学科样例、验收测试与上线支持 |

角色可由成员兼任，但安全、教研质量和发布验收必须有明确责任人，不能只以“功能可运行”作为上线标准。

### 1.2.2 2026 年 8 月上线功能基线

- 邮箱注册登录、HttpOnly Cookie 会话刷新、用户生成额度
- 五 Agent 顺序生成、实时进度、案例库编辑与版本管理
- 四项运行时 Skills 与 Skill trace：教学设计、案例类型、学科适配、案例包校验
- 一键生成/换一组 3 条教学目标，仍支持人工增删改
- 2800 字等目标字数的 95%–105% 质量门禁
- Word、PDF、PPTX 三格式导出；主题化文件名和版本号
- PPT 主题/密度/受众配置、目录预览和 WPS/PowerPoint 二次编辑
- Docker Compose 常驻部署，前端 5173、后端 8010

### 1.3 项目目标

| 维度 | 目标 | 验收标准 |
|------|------|----------|
| 功能 | 端到端教学案例生成流水线 | 教师 20 分钟内获得可授课的结构化案例包 |
| 质量 | 教学适用性 ≥ 85% | 教研专家抽样评审通过率 |
| 架构 | AutoGen 多 Agent 可编排、可扩展 | 新增 Agent 角色 ≤ 1 天接入 |
| 效率 | MVP 开发周期 ≤ 8 周 | 里程碑按时完成率 ≥ 90% |
| 成本 | Token 成本可控 | 单案例 API 成本 < ¥10 |

### 1.4 教学案例 vs 学术论文（范围澄清）

| 维度 | 学术论文 | 教学案例（本项目） |
|------|----------|-------------------|
| 目的 | 论证观点、发表成果 | 支撑教学、促进讨论与能力培养 |
| 结构 | 摘要、文献综述、方法、结论 | 情境、冲突、问题、讨论题、教师指南 |
| 读者 | 审稿人、同行 | 学生 + 授课教师 |
| 评价标准 | 创新性、严谨性 | 情境真实性、讨论价值、教学目标对齐 |
| 产出形态 | 长文 + 参考文献 | 案例正文 + 讨论题 + 教师手册 + 课件要点 |

### 1.5 AI + AutoGen 项目管理 vs 传统项目管理

| 维度 | 传统项目管理 | 本方案（AutoGen 多智能体） |
|------|-------------|---------------------------|
| 开发单元 | 功能模块 | **Agent 角色 + 对话编排（GroupChat/Sequential）** |
| 需求验证 | 原型 + 用户访谈 | **先跑通 Agent 协作链 + 样例案例评审** |
| 进度度量 | 人天 | **Agent 轮次、Token 消耗、案例质量 Rubric 分** |
| 测试 | 功能测试 | **案例质量评测集 + 多 Agent 对话回归** |
| 变更管理 | CR 单 | **Agent Prompt/编排 YAML 版本 + A/B 案例对比** |
| 核心风险 | 进度、人员 | **Agent 幻觉、角色冲突、案例失真、合规** |
| 交付物 | 代码 + 文档 | 代码 + **Agent 配置库 + 案例模板库 + 评测基准** |

## 2. 项目立项（Project Initiation）

### 2.1 商业论证

**问题**：案例开发依赖资深教师，产能不足；新课、新热点难以及时配套案例。

**方案价值**：
- 将单案例初稿周期从数周压缩至数十分钟
- 多 Agent 分工模拟「学科专家 + 教学设计 + 案例编写 + 质检」协作
- AutoGen 编排可复用，便于扩展新学科与新案例类型

### 2.2 项目章程

```
项目名称：CaseAutoGenSystem — AutoGen 教学案例自动生成系统
技术核心：Microsoft AutoGen (AG2) 多智能体对话编排
项目启动：2026 年 5 月
系统上线：2026 年 8 月
团队规模：4 人
项目投入：人民币 15 万元
项目周期：2026 年 5 月至 8 月；核心 MVP 研发 8 周（4 Sprint × 2 周）
成功标准：
  ✓ MVP：支持管理类/通用学科单案例全流程生成
  ✓ 产出：案例正文 + 讨论题 + 教师参考 + 教学目标对齐说明
  ✓ 质量：评测集 Rubric 综合分 ≥ 80
  ✓ 验证：5 名教师完成种子用户测试
```

### 2.3 干系人登记册

| 干系人 | 角色 | 关注点 |
|--------|------|--------|
| 教务/教研室负责人 | 决策者 | 教学质量、合规、成本 |
| 授课教师 | 主要用户 | 案例可用性、可编辑性、省时 |
| 学生 | 间接用户 | 案例有趣、可讨论 |
| 教研专家 | 评审者 | 教学目标对齐、讨论深度 |
| 开发团队 | 执行者 | AutoGen 稳定性、可维护性 |

### 2.4 AutoGen 项目立项特殊流程

```
Step 1: Agent Spike（2-3 天）
  → 用 Cursor 实现 3-Agent 最小链路（策划 + 撰写 + 评审）
  → 产出 1 份样例案例供教研评审

Step 2: 案例 Rubric 基线（并行）
  → 定义教学目标对齐、情境真实性、讨论价值等评分标准
  → 准备 5 份人工标杆案例

Step 3: 编排方案选型
  → Sequential vs GroupChat vs 自定义 Speaker Selection
  → 确定 MVP 编排模式

Step 4: 范围冻结 → Sprint 0
```

## 4. 产品研发过程管理

### 4.1 方法论：Agent-Driven Scrum

```
Sprint 周期：2 周

每日：
  - 站会同步 Agent 链路稳定性、昨日案例评测分
  - Cursor Agent 结对开发 Agent 配置与编排代码

Sprint 仪式：
  - Planning：User Story + Agent Task 联合排期
  - Mid-Sprint：跑评测集，决定是否调整 Agent Prompt
  - Review：向教师演示真实生成案例
  - Retro：Agent 协作效率与幻觉问题复盘
```

### 4.2 四阶段 Sprint 规划

#### Sprint 0（1-2 周）：AutoGen 基础设施

| 任务 | 交付物 |
|------|--------|
| AutoGen 环境 + LLM 配置 | 本地可运行 Agent 对话 |
| Agent 注册与配置框架 | YAML/JSON 定义 Agent 角色 |
| 案例结构化 Schema | Pydantic 模型（案例包 JSON） |
| 评测基础设施 | Rubric 脚本 + 样例集 |
| Web/API 脚手架 | FastAPI + 简单前端 |

#### Sprint 1（3-4 周）：核心 Agent 链路

| 任务 | 交付物 |
|------|--------|
| CasePlanner Agent | 案例结构与教学目标对齐 |
| DomainExpert Agent | 学科情境与专业知识 |
| CaseWriter Agent | 案例正文撰写 |
| Sequential 编排 | 三 Agent 顺序协作 |
| 参数配置页 + 生成触发 | 前端对接 |

#### Sprint 2（5-6 周）：协作增强与教师工作流

| 任务 | 交付物 |
|------|--------|
| PedagogyDesigner Agent | 讨论题、活动设计 |
| Reviewer Agent | 质量评审与修订建议 |
| GroupChat 编排 | 多轮协作修订 |
| 案例库 CRUD | 列表、详情、版本 |
| 人工编辑与版本管理 | 案例包统一保存、版本递增，避免局部重跑导致上下文错配 |

#### Sprint 3（7-8 周）：质量、导出与上线

| 任务 | 交付物 |
|------|--------|
| 质量门禁（Reviewer 阈值） | 低分自动重生成 |
| 导出 Word / PDF / PPTX | 授课材料包、可编辑课堂课件与目录预览 |
| 种子用户测试 | 教师测试报告 |
| 监控与成本 Dashboard | Token 与成功率 |
| 部署文档 | Docker 一键启动 |

## 5. 风险管理

### 5.1 风险登记册

| ID | 风险 | 概率 | 影响 | 应对 |
|----|------|------|------|------|
| R01 | Agent 编造虚假企业/事件细节 | 高 | 高 | DomainExpert 标注「虚构情境」；Reviewer 事实一致性检查 |
| R02 | 案例缺乏讨论价值（平淡无冲突） | 高 | 高 | CasePlanner 强制「冲突/决策点」结构；Pedagogy 专项评分 |
| R03 | 教学目标与案例内容脱节 | 中 | 高 | Planner 先锁定目标再生成正文；Rubric 强制对齐检查 |
| R04 | 多 Agent 对话失控/循环 | 中 | 中 | max_round 限制；终止条件；Speaker 规则 |
| R05 | Token 成本过高 | 中 | 中 | 分层模型；摘要传递上下文；缓存案例模板 |
| R06 | AutoGen 版本升级 breaking change | 中 | 中 | 锁定 ag2 版本；抽象编排层 |
| R07 | 教学伦理与版权风险 | 中 | 极高 | 用户协议；虚构标识；禁止抄袭真实未授权材料 |
| R08 | 教师不信任 AI 案例 | 中 | 高 | 可编辑；标注 AI 辅助；标杆案例对比演示 |
| R09 | 不同学科 Prompt 难以复用 | 高 | 中 | 学科模板插件化；Agent Prompt 按学科分包 |

### 5.2 质量门禁

| 门禁 | 时机 | 条件 |
|------|------|------|
| G1 Agent Prompt | Prompt 变更 | Rubric 下降 < 3% |
| G2 编排变更 | 编排逻辑修改 | 端到端样例案例通过 |
| G3 集成 | Sprint 中期 | 四件套产出完整 |
| G4 内容质量 | 保存与导出前 | 正文达到目标字数 95%–105%；无重复学科注释；目标、讨论题与对齐表完整 |
| G5 发布 | 上线前 | 邮箱认证、额度、DOCX/PDF/PPTX 冒烟测试 + 种子用户 + 合规审查 |

### 5.3 案例质量 Rubric（权重）

| 维度 | 权重 | 说明 |
|------|------|------|
| 教学目标对齐 | 25% | 案例支撑目标达成 |
| 情境真实性 | 20% | 背景合理、细节一致 |
| 讨论价值 | 25% | 冲突、多角度、无标准答案 |
| 结构完整性 | 15% | 四件套齐全、层次清晰 |
| 语言与可读性 | 15% | 适合目标学生水平 |

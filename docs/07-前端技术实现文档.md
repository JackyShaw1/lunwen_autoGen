## 1. 前端框架选型结论

### 1.1 推荐技术栈（MVP 采用）

| 类别 | 选型 | 版本建议 |
|------|------|----------|
| 框架 | **React** | 18.x |
| 语言 | **TypeScript** | 5.x |
| 构建 | **Vite** | 5.x |
| 样式 | **TailwindCSS** | 3.x |
| 组件库 | **shadcn/ui** + Radix UI | 最新 |
| 路由 | **React Router** | 6.x |
| 状态 | **Zustand** + React Query (TanStack Query) | 4.x / 5.x |
| 请求 | **axios** | 1.x |
| 实时 | 原生 **WebSocket** 或 `@stomp/stompjs` | — |
| 图表 | **Recharts** | 2.x |
| 富文本/Markdown | **@uiw/react-md-editor** 或 Tiptap | — |
| 表单 | **react-hook-form** + **zod** | — |
| 代码规范 | ESLint + Prettier | — |

### 1.2 候选方案对比

| 方案 | 优点 | 缺点 | 对本项目适配 |
|------|------|------|-------------|
| **React + Vite + TS** ★ | 生态成熟；Cursor/AI 生成质量高；组件化适合多页面工作台；WebSocket 集成简单 | 需自行组合技术栈 | **最佳**：复杂 B 端 + 实时 Agent 监控 |
| Next.js (App Router) | SSR/SEO、路由一体化 | 首页 SEO 需求弱；SSR 对纯工作台价值有限；与 FastAPI 分离部署时优势不明显 | 可选，非 MVP 必须 |
| Vue 3 + Vite | 上手快、模板清晰 | 团队与文档已统一 React；shadcn 生态偏 React | 可行但非首选 |
| Angular | 企业级规范 | 过重；迭代慢；AI 辅助效率一般 | 不推荐 |

### 1.3 为何 React 适合 CaseAutoGenSystem

本系统前端特征：

1. **多页面工作台**：统计看板、案例配置、Agent 流水线监控、四件套编辑、管理员 Agent 配置 — 适合 React 组件树 + 路由拆分。
2. **长时异步 + 实时推送**：案例生成 15 分钟级，需 WebSocket 更新 Agent 进度 — React 状态 + 订阅模式成熟。
3. **复杂表单**：创建案例多字段、动态教学目标列表 — `react-hook-form` + `zod` 与后端 Pydantic Schema 对齐。
4. **JSON 结构编辑**：CasePackage 四件套 — TypeScript 接口与后端 Schema 一一对应，减少联调错误。
5. **AI 辅助开发**：Cursor 对 React + Tailwind + shadcn 生成质量高，利于快速落地 MVP。
6. **与后端分离**：FastAPI 独立 API，Vite SPA 静态部署或 Nginx 反代，架构清晰。

**结论**：采用 **React 18 + TypeScript + Vite** 作为核心框架；**不推荐** 为此项目引入 Next.js，除非后续需要强 SEO 营销站独立拆分。

## 5. 状态管理策略

| 数据类型 | 方案 | 说明 |
|----------|------|------|
| 登录态、Token | **Zustand 内存态** + HttpOnly Refresh Cookie | 浏览器不保存密码；JS 无法读取 Refresh Token |
| 案例列表、详情、统计 | **TanStack Query** | 自动缓存、重试、失效刷新 |
| Agent 生成进度 | **WebSocket** → 组件 state 或 Zustand 切片 | 高频更新，不走 REST 轮询 |
| 表单草稿 | `react-hook-form` 内部状态 | 创建案例页 |
| UI（侧栏、Tab） | Zustand `uiStore` 或 URL 查询参数 | Tab 可用 `?tab=questions` |

**原则**：服务端数据用 Query；实时流用 WebSocket；不写全局 Redux。

## 6. API 与 WebSocket 集成

### 6.1 axios 客户端

```typescript
// lib/api-client.ts
const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',
  timeout: 30000,
  withCredentials: true,
});

api.interceptors.request.use((config) => {
  const token = authStore.getState().accessToken;
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

api.interceptors.response.use(
  (res) => res,
  async (err) => {
    if (err.response?.status === 401) {
      // 合并并发 refresh 请求；POST /auth/refresh 成功后重放原请求，否则跳转 /auth
    }
    return Promise.reject(err);
  },
);
```

### 6.2 核心 API 封装

| 模块 | 方法 | 端点 |
|------|------|------|
| 认证 | `register()`, `login()`, `refreshSession()`, `logout()` | `/auth/*` |
| 统计看板 | `getDashboardStats(range)` | `GET /dashboard/stats?range=month` |
| 案例 | `listCases()`, `createCase()`, `getCase(id)` | `/cases` |
| 教学目标 | `suggestObjectives(context)` | `POST /cases/suggest-objectives` |
| 生成 | `startGeneration(id)` | `POST /cases/{id}/generate` |
| 案例包 | `getPackage(id)`, `updatePackage(id, data)` | `/cases/{id}/package` |
| PPT 目录 | `fetchPptOutline(id, options)` | `POST /cases/{id}/ppt-outline` |
| 导出 | `exportCase(id, format, pptOptions?)` | `POST /cases/{id}/export` |
| Agent 配置 | `listAgents()`, `updateAgent(name, yaml)` | `/admin/agents` |

### 6.3 WebSocket（Agent 协作进度）

```typescript
// hooks/useGenerationWs.ts
export function useGenerationWs(caseId: string) {
  const [progress, setProgress] = useState<AgentProgress | null>(null);

  useEffect(() => {
    const ws = new WebSocket(`${WS_BASE}/ws/cases/${caseId}`);
    ws.onmessage = (e) => {
      const msg = JSON.parse(e.data);
      if (msg.type === 'agent_progress') setProgress(msg);
      if (msg.overall_progress === 100) ws.close();
    };
    return () => ws.close();
  }, [caseId]);

  return progress;
}
```

P05 页面用 `AgentPipeline` 组件消费 `progress.agents` 数组，与原型流水线 UI 对齐。

## 7. 页面实现要点

### 7.1 P03 工作台统计看板

| 模块 | 实现 |
|------|------|
| KPI 卡片 | `StatsCards` + Query `dashboard/stats` |
| 学科分布 | Recharts `BarChart` 横向条形 |
| 状态占比 | Recharts `PieChart` 或 CSS conic-gradient |
| 6 月趋势 | Recharts `BarChart` |
| 时间筛选 | `range` 状态 → Query `queryKey` 变化自动 refetch |
| 案例列表 | `CaseList` 表格/卡片，Query `cases` |

### 7.2 P04 创建案例

- `zod` Schema 与后端 `CaseTaskCreate` 对齐
- 动态字段：教学目标 `useFieldArray`
- 完成课程情境后可一键生成 3 条教学目标；再次点击换一组，生成结果仍可逐条编辑
- 编排模板下拉：`sequential_standard` | `groupchat_review`
- 提交成功 → `navigate(/case/${id}/generate)` 并 `POST generate`

### 7.3 P05 Agent 协作监控

- 进入页自动 `POST generate`（若未 running）
- WebSocket 实时更新各 Agent 状态：`pending | running | completed | failed`
- 展示 `output_summary` 折叠面板（教研调试）
- 完成 → 跳转 `CaseDetail`

### 7.4 P06 案例详情（四件套）

- Tab：正文 / 讨论题 / 教师参考 / 目标对齐
- 正文：按背景、叙事、时间线和决策点分区排版，使用标题、段距、卡片和留白控制长文阅读密度
- 支持编辑保存与版本递增；不提供局部 Agent 重新生成，避免四件套上下文错配

### 7.5 P07 Agent 配置（管理员）

- 子路由或 Tab：角色列表 / 编排 / Tool / 学科 / 全局 / 监控
- Prompt 编辑：大文本框 + 版本列表
- 参照 `06-Agent配置说明.md` 与原型 P07

### 7.6 P08 导出

- 格式单选：`docx` | `pdf` | `pptx`
- PPTX 增加主题（学术/现代/极简）、密度（简洁/标准/详细）、受众（教师/学生）配置
- 配置变化后防抖请求课件目录预览；确认后 `POST export`，返回带主题名和版本号的下载文件

## 8. TypeScript 类型（与后端对齐）

```typescript
// types/case.ts
export interface CaseTask {
  id: string;
```

## 12. 性能与安全

| 项 | 措施 |
|----|------|
| 首屏 | 路由级 `React.lazy` + `Suspense` |
| 列表 | Query `staleTime` 30s，看板 60s |
| 大文本编辑 | 案例正文分 Tab 懒加载编辑器 |
| XSS | Markdown 渲染用受信组件；禁止 `dangerouslySetInnerHTML` 直插用户内容 |
| 密码与会话 | 不在 localStorage/Cookie 保存密码；Refresh Token 仅由后端写 HttpOnly Cookie；生产环境强制 HTTPS |
| Token | `httpOnly` Cookie（推荐）或内存 + 短期 access + refresh |
| 权限 | 路由守卫 + API 403 统一处理 |
